# MVP 用户故事与验收清单

状态：需求拆分基线。产品规则以 [需求文档](requirements.md) 为准，组件边界以 [架构文档](architecture.md) 为准。每条故事在所列依赖完成后都能单独交付和验收；自动化测试使用确定性桩，不依赖付费模型、真实 RAG 服务或真实密钥。故事编号固定，后续拆分实施任务时保留原编号并追加子任务号。

统一完成门槛：相关 API 契约、前端交互和文档已同步；故事所列自动化测试及受影响的格式、类型、构建和回归检查通过；失败路径可由用户定位，密钥不进入日志、trace 或导出；按 [交付流程](workflow.md) 在本地提交。远程推送和 PR 更新需另行授权。下文的“完成标准”是每条故事额外的、可观察的验收条件。

## 工程与评测输入

### US-001 本机启动与质量门槛（依赖：无）

- **输入**：新克隆的仓库、受支持的 Python/Node 环境和本机配置示例。
- **输出**：独立启动的 React 前端、Python 管理 API 与 Worker，健康检查、版本化 OpenAPI 契约和一条统一检查命令；CI 在 PR 上运行同样的检查。
- **失败场景**：缺少依赖、配置无效、端口被占用、Worker 未启动时给出可定位的启动或健康检查错误；任一检查失败阻止绿色 CI。
- **自动化测试**：无密钥环境的安装/启动冒烟测试、健康检查与 OpenAPI 快照、前后端 lint/类型检查/构建及最小 pytest/组件测试。
- **完成标准**：新克隆仓库按 README 可启动、可运行统一检查命令，CI 对同一提交给出相同结果；管理 API 和前端默认只监听回环地址。

### US-002 导入并版本化金标准样本（依赖：US-001）

- **输入**：CSV/JSONL 文件与字段映射；每题含 `case_id`、问题，以及标准答案、有序参考 chunk 或两者；参考 chunk 含正文与 `document_id`。
- **输出**：不可变数据集版本、导入摘要和可浏览的样本详情；参考列表位置完整保留相关性顺序，答案型与检索型标注分别记录。
- **失败场景**：必填字段缺失、重复 `case_id`、空参考列表、同一文档下重复参考正文、错误文件格式均返回行号及原因，不产生半成品版本。
- **自动化测试**：三类样本的 CSV/JSONL 契约测试、顺序保持与版本不可变测试、逐行错误和导入原子性测试、前端导入错误展示测试。
- **完成标准**：答案型、检索型及混合型样本能独立或组合导入；旧版本在新导入或后续发布后仍可按原内容读取。

### US-003 导入已有预测批次（依赖：US-001、US-002）

- **输入**：CSV/JSONL 预测文件、字段映射和可选数据集版本；记录包含 `case_id`、答案和/或按检索顺序排列的预测 chunk，chunk 含正文及 `document_id`。
- **输出**：不可变 `PredictionBatch`、匹配/未匹配数量、行级错误和前端预览；允许从同一文件建立数据集并导入预测。
- **失败场景**：重复或未知 `case_id`、按选定评测类型缺少答案或上下文、坏 JSON、缺少 chunk 正文/文档 ID 时不把错误行当作成功预测。
- **自动化测试**：文件映射与规范化契约测试、单文件建集测试、错误行与批次原子性测试、顺序保持测试；断言导入过程没有目标 HTTP 请求。
- **完成标准**：文件预测与等价 HTTP 预测可归一化为同一结构，且之后的评分只引用已保存批次。

### US-004 异步运行与状态控制（依赖：US-002、US-003）

- **输入**：数据集版本、已保存预测批次、选定指标和运行参数。
- **输出**：带输入及指标配置快照的运行、进度、每题状态/错误、取消结果和可恢复查询的运行列表。
- **失败场景**：重复任务投递不重复写结果；单题失败保留其他题结果；取消后不提交新题；缺失 Worker、非法状态迁移及批次/数据集不匹配有明确错误。
- **自动化测试**：状态机和幂等单元测试、队列/数据库集成测试、单题失败/取消/重试测试、前端进度与错误状态测试。
- **完成标准**：API 请求不等待整批完成；运行可从 `queued` 到终态，逐题失败不被聚合为成功，历史快照不可变。

## 检索评测与结果

### US-005 本地向量模型与匹配候选（依赖：US-002、US-003）

- **输入**：本地模型标识或目录、模型专属相似度阈值、参考/预测 chunk，以及用于校准的代表性样本。
- **输出**：本地权重首次下载与缓存或离线加载、向量缓存、同文档 ID 候选余弦相似度及阈值预览；模型/阈值写入运行配置。
- **失败场景**：权重下载失败、离线目录缺失、模型不兼容、编码失败时给出诊断，不以文档 ID 相同直接视为命中，也不调用 SaaS 向量服务或生成式模型。
- **自动化测试**：本地模型桩的下载/离线/缓存测试、跨文档与阈值边界测试、预览契约测试、网络桩断言检索路径无外部模型调用。
- **完成标准**：同一模型版本与正文复用向量；更换模型或阈值产生新的候选判定输入，预览能解释命中或未命中。

### US-006 一对一 chunk 计分（依赖：US-005）

- **输入**：有序参考 chunk、有序预测 chunk、候选相似度、模型阈值、匹配及增益规则版本；K 分别为 10、20。
- **输出**：每个 K 的最大命中数一对一配对、被排除原因、Precision@K、AP@K、NDCG@K，以及运行级 MAP@K；保存相似度、配对和规则版本。
- **失败场景**：跨文档、低于阈值及重复预测 chunk 不增加命中；合并 chunk 只命中一次；预测不足 K、零预测、多解配对均按确定性规则计分。
- **自动化测试**：公式表驱动测试；合并预测 1 个命中时 `Precision@10=0.1`、`AP@10=0.5`；最大匹配反例配为 `1-B、2-A`；交换参考高低相关 chunk 的预测顺序仅改变 NDCG；重复项占位但无增益；K=10/20 独立匹配和稳定决议测试。
- **完成标准**：所有边界结果与需求文档公式一致，同一输入/规则版本多次运行得到相同配对及分数，历史判定不被新规则覆盖。

### US-007 查看并导出运行结果（依赖：US-004、US-006）

- **输入**：已完成或部分失败的运行 ID、筛选和导出格式。
- **输出**：运行列表、总体指标及分布、有效/失败/不适用数量、逐题答案与有序 chunk、相似度/阈值/配对证据、耗时、错误及 CSV/JSON 导出。
- **失败场景**：无有效检索题时指标显示不适用而非 0；单题失败不进入均值；文件预测无目标调用耗时；不存在的运行返回明确错误。
- **自动化测试**：聚合分母/失败/不适用单元测试、导出与 API 字段一致性测试、前端列表到详情及下载 E2E。
- **完成标准**：任一总体分数可定位到参与聚合的逐题结果及原始证据，导出值与屏幕/API 一致。

## 被测 RAG 接入与回答评测

### US-008 通用 JSON HTTP 目标（依赖：US-004）

- **输入**：目标 URL、可选 Bearer 凭据、超时/重试限制、连接测试问题，以及数据集版本；调用体含 `case_id` 和 `question`。
- **输出**：连接测试结果和不可变预测批次；响应中的答案、有序 `contexts`、可选 usage、请求耗时和逐次尝试状态归一化保存。
- **失败场景**：认证失败、超时、非 2xx、无效 JSON、按评测类型缺少答案/上下文或 chunk 字段时记录逐题失败，凭据不进入结果。
- **自动化测试**：本地假目标的成功、Bearer、超时、坏响应及重试契约测试；断言并发上限、请求体和规范化预测顺序。
- **完成标准**：JSON 目标可在运行前测试连接；有效响应与等价文件预测的评分输入一致，失败题不阻塞其他题。

### US-009 通用 SSE 目标与计时（依赖：US-008）

- **输入**：同一目标配置，带 `stream: true` 的请求；`answer.delta`、`contexts`、`completed` 或 `error` SSE 事件。
- **输出**：拼接答案、按原顺序保存的上下文、首个非空回答增量 TTFT、最后增量 TTLT、完成耗时及每次重试的计时/状态。
- **失败场景**：流内 `error`、意外断流、缺少 `completed`、缺少必要回答增量或上下文均失败；心跳、空增量与 `contexts` 不作为 TTFT。
- **自动化测试**：事件乱序（上下文早/晚）、空增量、错误事件、断流、无结束事件与重试的流式契约测试；等价 JSON/SSE 规范化结果对照。
- **完成标准**：只有 `completed` 后生成成功预测；流式和非流式的业务输入等价，三项计时定义可由测试时钟复现。

### US-010 保存场景评价标准并预览（依赖：US-001、US-002）

- **输入**：命名场景，忠实度、相关性、正确性三项可编辑评价标准，预览样本和在线 OpenAI 兼容评分模型配置。
- **输出**：场景版本、只读的系统提示词结构/变量/输出格式、单题预览分数及原因、运行可选场景列表。
- **失败场景**：空或过长标准、预览样本缺少必需输入、模型不可用、结构化输出无效时预览失败并保留原场景；用户不能改系统提示词骨架。
- **自动化测试**：场景 CRUD/版本测试、固定模板渲染测试、模型桩的预览成功与坏响应测试、前端编辑和错误提示测试。
- **完成标准**：可按场景复用三项标准；修改后形成新版本，旧运行引用的标准与系统提示词版本仍可读取。

### US-011 回答质量评分（依赖：US-004、US-010）

- **输入**：保存的预测批次、金标准答案/预测上下文、选定场景版本和在线评分模型配置。
- **输出**：忠实度、相关性、正确性各自 0–1 分数、评分原因、适用性、原始模型响应与模型/参数快照，结果页逐题及总体展示。
- **失败场景**：忠实度缺上下文、正确性缺标准答案标为不适用；模型超时、非法分数或结构化输出错误记为该题该指标失败，不伪造 0 分或总分。
- **自动化测试**：三项指标适用性矩阵、固定提示词与解析契约、0/1 边界、模型失败隔离和聚合分母测试；离线模型桩完成前端结果 E2E。
- **完成标准**：每项分数都能追溯场景标准、系统提示词版本、模型与原因；缺标注和调用错误与真实 0 分可区分。

### US-012 复用预测结果重新评分（依赖：US-006、US-011）

- **输入**：历史运行 ID、新场景版本或检索模型/阈值/规则版本选择。
- **输出**：引用原不可变预测批次的新运行；配置未变时复用已保存匹配判定，配置变化时生成新判定，旧结果保持原样。
- **失败场景**：预测批次不存在、配置无效、部分预测失败时明确标记；任何复评路径均不得再次调用被测 RAG。
- **自动化测试**：目标 HTTP 桩调用计数恒为 0、相同配置缓存命中、变更模型/规则重新判定、历史运行快照不变测试。
- **完成标准**：用户可对保存的答案和检索结果选择新标准复评，比较两次运行的配置与逐题原因而不重新获取预测。

## 文档来源与样本生成

### US-013 上传文本原文并固定文档集合（依赖：US-001）

- **输入**：TXT/Markdown 原始文件、逐文件自填或自动生成的 `document_id`、切块大小与重叠量。
- **输出**：保留原始字节、文件校验值、`document_id` 和有序切块的不可变集合快照；自动 ID 采用文档名称加自增序号。
- **失败场景**：重复/空文档 ID、空文件、无效切块参数或非法编码给出文件级错误，不留下半成品集合；MVP 不提供原文内容更新。
- **自动化测试**：原始字节/校验值、自动 ID 唯一性、手填 ID 保持、切块参数与结果快照、导入原子性及前端上传测试。
- **完成标准**：集合显示将交给被测 RAG 的确切文档 ID 和原文校验值；后续切块设置修改不改变已有集合。

### US-014 解析 DOCX 与文本 PDF（依赖：US-013）

- **输入**：DOCX 或可提取文本的 PDF 原始文件及与 US-013 相同的 ID/切块设置。
- **输出**：可用于切块和生成的提取文本，同时保留原始文件字节、文件名和校验值。
- **失败场景**：损坏文件、无可提取文本的扫描 PDF、受保护 PDF 或不支持类型返回可定位错误，不生成空文本集合；不执行 OCR。
- **自动化测试**：小型 DOCX/文本 PDF 固定样本提取与原字节测试、扫描/损坏/不支持文件拒绝测试、文件级前端错误展示测试。
- **完成标准**：支持的文件生成可检查的文本 chunk；下载时仍取到上传的原始文件而非提取后的文本。

### US-015 导入已有 chunk 清单（依赖：US-013）

- **输入**：含有序 chunk 正文与 `document_id` 的清单及集合元数据，无原始文档文件。
- **输出**：可用于候选生成和评测的不可变 chunk 集合，明确标记不存在原始文件。
- **失败场景**：缺少正文或文档 ID、非法顺序、重复或空清单给出行级错误；不得推断或伪造原文。
- **自动化测试**：清单解析、顺序与 ID 保持、原子性、原文缺失标记和前端导入测试。
- **完成标准**：chunk-only 集合能进入生成流程，但原文下载入口不会为它生成文件 URL。

### US-016 用独立 Token 下载原文（依赖：US-013、US-015）

- **输入**：集合 ID、专用下载 Bearer Token、配置的监听地址和对外 URL；仅原文集合有可下载文件。
- **输出**：远程可读的 manifest（`document_id`、文件名、校验值、下载 URL）及原始字节文件；下载进程与管理 API 独立监听。
- **失败场景**：缺失/错误 Token、未知文件、chunk-only 集合请求文件、路径穿越返回受控错误；下载入口不暴露管理 API，也不记录对方导入状态。
- **自动化测试**：manifest 与校验值/字节一致性、Bearer 正反例、路径穿越、chunk-only 无文件、下载入口路由隔离与监听配置测试。
- **完成标准**：持 Token 的远程客户端可按 manifest 下载并验证原文，返回的 ID 与上传时确定的 ID 一致。

### US-017 按配额生成候选样本（依赖：US-010、US-013、US-015）

- **输入**：集合快照、目标条数、多 chunk 题目标比例、语言、题型、补充要求，以及独立配置的在线 OpenAI 兼容生成模型。
- **输出**：异步任务状态与进度、固定核心提示词版本和配置快照、分布到文档内容的候选问题/标准答案/有序支撑 chunk、目标与实际数量及不足原因。
- **失败场景**：模型超时/坏输出、内容不足、并发或调用次数上限触发时保留合格候选供审核；多 chunk 目标不足不由其他题型自动填补。
- **自动化测试**：模型桩验证配额分配、多 chunk 必要支撑、chunk 来源、提示词快照、进度与部分失败、不足额报告、并发/调用上限。
- **完成标准**：候选均可追溯集合、模型和提示词版本；未达到目标时用户能看到实际条数及原因，不会误认为已完成配额。

### US-018 审核与编辑候选（依赖：US-017）

- **输入**：待审核候选及当前集合可选 chunk；审核者修改问题/标准答案，增删、替换或重排参考 chunk。
- **输出**：候选修订记录、审核状态及按相关性从高到低排列的参考列表；被批准候选可进入发布校验。
- **失败场景**：直接改写 chunk 正文、选择其他集合 chunk、移除全部参考 chunk 或漏填答案时拒绝批准并指出字段。
- **自动化测试**：编辑权限与来源校验、重排持久化、修订历史/状态迁移测试、前端审核流程 E2E。
- **完成标准**：审核者能修正答案和支撑证据，但发布用 chunk 仍引用当前集合中未经改写的正文；未批准候选不可评测。

### US-019 同集合查重与疑似重复放行（依赖：US-017、US-018）

- **输入**：生成后或审核修改后的候选，以及同一集合历次候选和已发布题目。
- **输出**：明确重复/疑似重复/非重复判定、对比证据、疑似重复的人工确认与放行理由审计记录。
- **失败场景**：同一事实且答案相同的明确重复不得发布；疑似重复无理由或修改后未重新查重不得放行；查重错误阻止发布而非默认通过。
- **自动化测试**：完全相同与改写同事实样本、跨批次/已发布查重、疑似放行理由、修改后重查及失败阻断测试。
- **完成标准**：每条待发布候选均有当前内容对应的查重结论；疑似放行可追溯原判定、审核者决定与理由。

### US-020 发布候选为不可变数据集版本（依赖：US-002、US-018、US-019）

- **输入**：已批准且通过字段/查重校验的候选，选择新建数据集或已有数据集。
- **输出**：新数据集首版或已有数据集新版本，保留稳定 `case_id`、答案、有序参考 chunk 及所引用的集合快照。
- **失败场景**：未批准、重复、缺字段、`case_id` 冲突或版本竞争时拒绝整个发布事务；不改写历史版本，也不伪造缺失证据。
- **自动化测试**：新建/追加版本、原子性、版本竞争与冲突、旧版不变、发布后可按 US-004 评测的集成测试。
- **完成标准**：发布成功后的版本可作为普通导入版本使用；失败不会留下半发布数据，历史版本内容逐字不变。

## 可观测性与容量

### US-021 记录模型 token 用量（依赖：US-005、US-008、US-011、US-017）

- **输入**：生成、回答评分、本地向量生成每次调用的请求/响应、模型标识和在线接口可选 usage；目标 RAG 可选返回 usage。
- **输出**：逐次输入/输出 token、实际或本地分词器估算来源、模型及运行/生成任务汇总；向量输出 token 标为不适用。
- **失败场景**：在线接口无 usage 时只估算本系统可见调用；被测 RAG 不返回 usage 时标记未知，不推断其内部提示词；计数失败不伪称实际值。
- **自动化测试**：实际 usage、缺失 usage 估算、向量输出不适用、目标 usage 有/无、汇总与来源区分测试。
- **完成标准**：每项任务可解释 token 总数由哪些调用构成，并能区分实际、估算、不适用和未知。

### US-022 全链路 trace 与保留期提示（依赖：US-002、US-004、US-006、US-008、US-011、US-017、US-021）

- **输入**：数据导入、生成、运行、目标调用、匹配、评分与落库事件，API 到 Worker 的任务消息及 Jaeger 保留期配置。
- **输出**：OpenTelemetry 关联的运行/样本/批次/重试 span、结果页 Jaeger 链接和过期状态；全文留在业务记录并以 trace ID 关联。
- **失败场景**：Jaeger 不可用或 trace 过期不影响业务结果；问题、chunk 正文、提示词、模型原始响应、密钥和认证头不得进入 trace。
- **自动化测试**：跨队列上下文传播、span 关联/失败状态、敏感字段白名单、Jaeger 不可用及 30 天默认/可配置过期提示测试。
- **完成标准**：一次运行可由结果定位完整评测链路；过期后仍可查看逐题业务证据，trace 中只含允许的元数据。

### US-023 千题规模与故障恢复（依赖：US-004、US-007、US-008、US-009、US-011）

- **输入**：100–1,000 条混合标注样本、受控并发/超时/重试参数和确定性目标/模型桩。
- **输出**：可观察的预计外部调用量、稳定进度、逐题成功/失败/不适用统计、完整导出和可重启后查询的运行结果。
- **失败场景**：目标限流、模型超时、Worker 重启、重复消息、用户取消时保持并发上限、结果幂等及明确终态，不无限重试或丢失已完成题目。
- **自动化测试**：1,000 题本机集成负载、限流/超时/重启/取消故障注入、结果数量与聚合一致性及浏览器关键路径 E2E。
- **完成标准**：固定桩的 1,000 题 CI 负载在 10 分钟内结束并记录测试环境与耗时；故障后所有题目均有明确状态且导出无重复。

## MVP 整体验收

在 CI 无真实密钥的条件下，用固定文档、金标准样本、预测文件、JSON/SSE 假目标和模型桩，贯通“上传或导入文档 → 下载原文 → 生成并审核发布样本 → 导入/调用预测 → 运行检索与回答评测 → 复评 → 查看/导出结果”。每个故事通过后才标记完成；整体验收还须验证前后端契约一致、MVP 范围外功能未被误当作交付，以及 PR 的必需检查全绿。建议先交付 US-001～US-007 的文件评测闭环，再接入 HTTP 与回答评分；文档来源/生成流程可在工程基座就绪后并行推进。

## 1.1 前端界面

以下故事执行 [1.1 前端界面需求](requirements.md#11-前端界面需求已确认)。每条故事完成后运行 `make check` 并本地提交；远程交付另行授权。

### US-024 统一视觉与主导航（依赖：US-001）

- **输入**：现有八页主导航、用户提供的 AIA 官网视觉参考和 ragEva 品牌。
- **输出**：统一的红/粉/白/深灰设计变量、导航和页面标题、基础按钮/输入/焦点样式；桌面常驻导航和窄屏完整导航。

- **自动化测试**：组件测试覆盖八页导航和窄屏菜单状态；浏览器测试覆盖桌面与窄屏导航切换、键盘焦点和页面整体无横向溢出。
- **完成标准**：八页从导航均可到达并可返回，主要命令和状态清晰，320px 宽度下仍可完成导航。

### US-025 业务页面统一样式（依赖：US-024）

- **输入**：文档集合、候选生成、数据集、预测批次、HTTP 目标、评价场景、评测运行及系统状态现有数据与 UI 状态。
- **输出**：八页的表单、列表、详情、表格、弹窗、空态、错误态与状态提示采用同一视觉规则，保留原有业务信息密度与操作。
- **失败场景**：改版导致字段、评测指标、证据或错误详情不可见，弹窗内容被截断，列表选中态不清楚，上传/审核/导出入口失效。
- **自动化测试**：现有页面组件测试和浏览器业务闭环回归；补充主要页面空态与有数据状态的布局、表单和弹窗可操作测试。
- **完成标准**：八页的常用任务无需学习新的业务流程，桌面截图显示一致的层级、控件和状态样式。

### US-026 窄屏、可访问性与视觉验收（依赖：US-024、US-025）

- **输入**：完成统一样式的八页以及 320px、390px 和桌面视口。
- **输出**：可触达的窄屏导航与命令、自适应表单/详情、可见键盘焦点和视觉验收记录。
- **失败场景**：页面整体横向滚动、最长标签遮挡控件、列表详情重叠、仅靠颜色表达成功/失败、键盘无法打开或关闭菜单。
- **自动化测试**：Playwright 在桌面与窄屏逐页检查导航、溢出和核心操作；保留原有全链路 E2E，人工核对对应截图。
- **完成标准**：八页在约定视口均无整体溢出或内容遮挡，菜单与关键表单可用，`make check` 全绿。

### US-027 标题层级与留白细化（依赖：US-024、US-026）

- **输入**：第二张 AIA 官网截图所示的醒目标题、宽松段落间距与文字入口，以及现有八页的标题和操作按钮。
- **输出**：更明确的页面/区块标题层级与标题下方留白，仍适合评测工作台的扫描密度；不加入官网人物照片或营销内容。
- **失败场景**：标题与操作按钮重叠、320px 下标题被强行截断、标题放大挤掉表单或关键命令时不得视为完成。
- **自动化测试**：Playwright 在 320px、390px 和桌面视口逐页检查标题与操作区位置、页面溢出，并运行原有业务闭环。
- **完成标准**：八页标题和操作区视觉分层清楚，窄屏仍可完整阅读与操作，`make check` 全绿。

### US-028 八页系统文案双语化（依赖：US-025、US-026）

- **输入**：现有八页的系统自有文案、导航和弹窗、图标可访问名称、空态/加载态/错误态，以及用户输入和后端返回的原始业务内容。
- **输出**：系统文案统一显示为英文在前、中文置于全角括号内的 `English（中文）`；导航、表单、状态和可访问名称语义一致。用户内容、技术标识与原始业务数据保持原样。
- **失败场景**：任一页面或弹窗出现仅中文/仅英文的系统说明、英文与中文含义不一致、图标按钮只有单语名称、错误详情被伪造翻译、上传内容或导出数据被改写、双语文案在窄屏遮挡控件。
- **自动化测试**：组件测试检查八页常用操作、弹窗、加载/空态/错误态的双语文本与可访问名称；Playwright 逐页检查导航和标题，抽查表单、状态、图标工具提示及 320px 布局；用中文问题/文档名和模型回答验证用户内容原样显示，原业务 E2E 继续通过。测试案例见 `AT-15`。
- **完成标准**：系统自有文案无遗漏且遵循同一格式，原始内容不变，八页可用；双语测试和完整 `make check` 均通过。

### US-029 数值单位与大小明确展示（依赖：US-028）

- **输入**：切块大小/重叠量、原始文件字节数、超时、耗时、token 用量、多 chunk 比例、各种数量、相似度阈值与评分等已有数值及空值。
- **输出**：所有有量纲的输入和读数就地标注正确的双语单位；切块与重叠按 `characters（字符）`、文件按精确 `bytes（字节）`、超时按 `seconds（秒）`、耗时按 `ms（毫秒）`、用量按 `tokens（词元）`、比例按 `%（百分比）` 显示；阈值和评分明确为 `0–1（无单位）`，计数标明对象。后端收到的数值不变。
- **失败场景**：把字符数误标为字节/token、KB/MB 四舍五入后丢失精确文件大小、秒与毫秒混用、比例与 0–1 数值混用、未知值伪装为零、单位只在帮助文字出现、双语单位在窄屏被截断。
- **自动化测试**：组件测试验证上传表单的 `1000` 字符和 `100` 字符重叠提交值不变、精确字节数及秒/毫秒/token/%/无单位格式化和空值；Playwright 检查上传弹窗、文档详情、生成、目标和运行页在 320px/桌面端的单位与布局；原业务 E2E 继续通过。测试案例见 `AT-16`。
- **完成标准**：相关输入、详情和汇总读数均能直接判断数值含义，原有 API 语义和校验保持一致，完整 `make check` 通过。
