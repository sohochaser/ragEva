# 候选生成

生成任务接受原文或 chunk-only 集合的不可变快照。先在“候选生成”页添加或选择在线 OpenAI 兼容模型，再设置目标条数、多 chunk 比例、语言、题型和补充要求。模型请求使用固定核心提示词 `candidate-generation-v1`，任务快照保存模型标识、非敏感参数、用户要求和提示词版本；Bearer Token 仍只保存在本机受保护的模型密钥文件中。

多 chunk 目标数为 `ceil(目标条数 × 比例)`，其余为单 chunk 目标。来源先按文档交错、再按各文档的 chunk 顺序轮转，每次单 chunk 题提供一个来源，多 chunk 题提供两个不同来源。模型必须返回问题、标准答案和按相关性排序的来源位置列表；系统据此从集合快照回填 `document_id` 与原文，拒绝未知位置、重复位置、空答案及支撑不足的多 chunk 输出。生成候选保存为 `pending_review`。

任务经 Huey Worker 异步执行，状态为 `queued`、`running`、`completed`、`partial` 或 `failed`。默认最多调用 `目标条数 × 3` 次模型接口，最多同时 4 次；用户可在创建时收紧调用上限和并发量。失败的配额会在调用上限内重试，已合格候选始终保留。集合不足两个 chunk 时，多 chunk 配额不会由单 chunk 题目填补。任务接口返回目标/实际条数、调用进度、错误次数与不足原因；合格响应的模型 usage 如有返回会保存到逐次尝试，统一汇总和估算由 US-021 实现。

候选审核提交问题、标准答案和有序 `support_positions`，只能引用当前集合的 chunk；服务端从不可变集合回填正文与 `document_id`，拒绝直接传入改写后的参考正文或跨集合位置。保存允许不完整草稿，批准要求非空问题、答案和至少一个参考 chunk；驳回保留当前内容。状态为 `pending_review`、`approved` 或 `rejected`，编辑已批准候选会退回待审核。每次操作保存完整修订快照及修订号，过期修订号返回冲突提示。参考列表顺序由审核者按相关性从高到低排列。生成时的多 chunk 配额标记仍表示原生成任务类型，审核后的实际证据以当前参考列表为准。只有已批准候选可进入后续查重与发布校验；查重和发布不属于当前审核接口。
