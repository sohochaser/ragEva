# 产品需求草案

状态：MVP 范围草案；chunk 语义匹配的实现方式待确认。目标是给开发者一套可复现、可追溯的本机 RAG 评测工作台。已确认：一套 Python 后端、React 前端，前后端分离，本机单人使用；单次评测约 100 到 1,000 条样本。

## 已确认的评测对象

首版评测单轮文本 RAG 的检索效果和最终回答，但两类标注的用途不同：端到端答案样本包含问题和标准答案，用于回答质量评测；chunk 召回样本包含问题、一个或多个参考 chunk、这些 chunk 从高到低的相关性顺序，以及每个 chunk 对应的相关文档 ID，用于检索评测。两类样本既可独立导入，也可在同一题中共存。参考和预测 chunk 主要有正文与 `document_id`，通常没有可共享的稳定 chunk ID；正文可能截断或改写，因此需要语义匹配。被测系统返回的 chunk 顺序是预测排序，不能与参考 chunk 的相关性顺序混同。检索指标以 chunk 为命中单位，文档 ID 用于限定候选与解释来源；同一文档的不同 chunk 不能合并为一次命中。

## 用户与主流程

主要用户是本机上的 RAG 开发者。用户导入带问题、标准答案和/或有序参考 chunk 的样本；选择调用现有 RAG HTTP API 或导入已有答案、检索结果；配置指标、评测模型与场景评价标准；运行评测；查看总体分数和逐样本证据；导出结果。失败样本可定位到调用错误、导入错误、缺失上下文或具体评分原因。

## MVP 范围

1. 数据集：导入 CSV/JSONL，字段映射与校验；不可变版本。每条样本有稳定 ID 和问题。答案样本需要标准答案；检索样本需要非空的有序 `reference_chunks` 列表。列表位置就是从高到低的参考相关性顺序，每个 chunk 需要正文和 `document_id`，不要求数值分数或共享 chunk ID。允许两类样本独立导入，也允许同一题同时带两类标注；按实际存在的标注计算对应指标，缺少另一类标注时标记为不适用。拒绝缺少必要字段、重复样本 ID、空参考列表或同一文档下正文完全相同的重复参考 chunk，给出行号与错误原因。
2. 输入方式：HTTP 模式先使用约定的 JSON 契约调用 RAG 服务，支持创建运行前测试连接；真实系统的特定格式通过后续适配器支持。文件模式导入 CSV/JSONL 中已有的答案和/或有序预测 chunk，可按样本 ID 匹配已有数据集，也可从同一文件建立数据集。两种方式都归一化为按评测类型提供的答案、预测 chunk 正文及其文档 ID/来源、耗时（若有）和错误；chunk ID 可选。只做检索评测时答案不必存在，只做回答评测时需要答案，忠实度还需要预测上下文。导入时显示未匹配、重复和缺失字段的行级错误；HTTP 密钥留在后端。
3. 运行：选择数据集版本、HTTP 目标或已保存的预测批次，以及指标集，异步执行；首版支持约 100 到 1,000 条样本，并限制同时运行的评测及外部请求数量。HTTP 调用与文件导入都生成不可变预测批次。可查询进度、取消、失败原因；对单个样本失败进行记录，不把整批结果伪装成成功。使用已有预测批次时不得再次调用被测 HTTP 服务。每次运行固定输入来源快照、指标版本、评测模型与参数。
4. 指标：检索指标为 Recall@K、MRR@K、NDCG@K，均以参考 chunk 与预测 chunk 的语义匹配和预测排序为依据；相同文档 ID 本身不算命中。先按文档 ID 限定候选，再判断预测 chunk 是否保留了参考 chunk 对该问题的关键证据。预测 chunk 合并多个参考 chunk 时的命中归属待确认。NDCG@K 使用参考顺序推导的相关性增益，具体归属与增益规则见待确认项。语义判定结果需记录模型、提示词版本、判定理由并缓存，因此检索指标属于评测模型辅助指标。回答指标为基于上下文的忠实度、答案相关性和相对于标准答案的正确性，主要由大模型按提示词评判。评测模型通过可配置地址、模型名和凭据的 OpenAI 兼容 API 接入，可使用云端或本地服务。逐项记录原始分数、适用性、错误和评分依据；模型辅助指标标注非确定性，不与其他指标混为一个总分。
5. 评价标准：系统固定三项回答指标的提示词结构、输入变量和结构化评分输出；用户只编辑各指标的评价标准，并将三项标准作为一个命名场景保存和复用。运行时选择一个场景，运行前可用单条样本预览评分结果。每次运行保存场景标准内容、版本及系统提示词版本快照，避免后续修改影响历史结果。
6. 结果：运行列表、总体指标和分布、逐样本详情、CSV/JSON 导出；显示有效样本数、失败数和不适用数。

## MVP 验收场景

1. 导入答案样本或 chunk 召回样本后，系统生成不可变版本；缺少各自必要字段、参考 chunk 列表为空或重复样本 ID 会标明具体行号，且不会生成半成品版本。参考列表的数组位置保留相关性顺序，不把它改写成预测排序。
2. 对约定 HTTP 接口运行评测时，每条结果可查看答案、预测 chunk 顺序和正文、对应文档 ID、调用耗时、指标分数、语义匹配判定与失败原因；接口单条失败不抹掉其他样本的结果。
3. 导入相同答案和检索片段的结果文件后，不发生目标 HTTP 调用；相同数据集、预测内容和语义匹配配置复用已缓存的判定，因此文件与 HTTP 两种模式的检索分数逐样本一致。更换匹配模型或规则会形成新的评测版本，而不覆盖历史判定。
4. 检索指标分别以 K=10 和 K=20 在预测 chunk 的 Top-K 上计算：Recall@K 为命中的参考 chunk 数除以参考 chunk 总数；逐样本 RR@K 为首个命中参考 chunk 的预测位置倒数，未命中为 0，运行级 MRR@K 为有效检索样本 RR@K 的均值；NDCG@K 按参考 chunk 顺序推导的增益和预测位置折损计算，未命中为 0。K 计数使用预测列表的实际位置；重复返回同一 chunk 不得重复增加召回。合并 chunk 的计数及 NDCG 归属规则确认后补充边界样例。
5. 修改场景评价标准后，可从已有运行发起重新评分，复用不可变预测批次且不再请求被测 RAG 服务；新运行使用新标准，历史运行仍能查看当时的标准、系统提示词版本、模型配置、逐样本评分和评分原因。
6. 报告显示评测配置、有效样本数、失败数和不适用数，并可导出逐样本结果。

## 首版不做

不自建向量库或知识库，不承担 RAG 推理，不做在线流量采集、多轮对话、自动生成测试集、两次运行的对比或自动判定上线。首版聚焦单轮文本问答的离线评测。

## 质量与安全约束

- 语义匹配与回答评分依赖评测模型，首次判定可能存在波动；相同数据集、预测批次与评测配置复用已保存的判定和评分快照时必须得到相同结果。外部调用的输入输出与错误需要可追溯，敏感值必须脱敏。
- API 与前端分离，使用版本化 JSON 契约；长任务不占用 API 请求生命周期。
- 运行并发、超时、重试和评测模型调用次数设置上限，运行前显示预计调用次数；取消后不再提交新样本。
- 服务默认只监听本机回环地址；外部目标地址由本机用户配置，密钥不能写入运行结果、导出文件或日志。
- 自动化验收覆盖数据校验、指标边界、任务状态迁移、API 契约以及核心前端流程。

## 实现默认值

1. 评测模型由用户配置地址、模型名与凭据；运行前展示模型目标地址和预计评测调用次数。
2. 通用 HTTP 契约支持可选 Bearer Token，默认 30 秒超时；两者均可在目标配置中调整。
3. 每项回答指标输出范围为 0 到 1 的分数及评分原因。系统维护输入变量与结构化输出格式，场景只保存可编辑的评价标准。

## 待确认的检索标注细节

1. 首版语义匹配使用已配置的评测大模型、独立向量模型，还是两者结合。
2. 一个预测 chunk 覆盖多个参考 chunk 时，命中归属、Recall 计数与 NDCG 增益如何计算。
