# 产品需求草案

状态：范围草案，待确认具体接口和评测模型。目标是给开发者一套可复现、可比较、可追溯的本机 RAG 评测工作台。已确认：一套 Python 后端、React 前端，前后端分离，本机单人使用。

## 用户与主流程

主要用户是本机上的 RAG 开发者。用户导入带问题和可选参考答案、相关文档标注的数据集；选择调用现有 RAG HTTP API 或导入已有答案与检索结果；配置指标和评测器；运行评测；查看总体分数和逐样本证据；比较两次运行；导出结果。失败样本可定位到调用错误、导入错误、缺失上下文或具体评分原因。

## MVP 范围

1. 数据集：导入 CSV/JSONL，字段映射与校验；不可变版本；逐样本标识、问题、参考答案、相关文档 ID 为可选字段。拒绝缺少问题、重复 ID 或不合法结构，给出行号与错误原因。
2. 输入方式：HTTP 模式通过适配器调用已有 RAG 服务，支持创建运行前测试连接和字段映射；文件模式导入 CSV/JSONL 中已有的答案与有序检索片段，可按样本 ID 匹配已有数据集，也可从同一文件建立数据集。两种方式都归一化为答案、检索片段及片段 ID/来源、耗时（若有）和错误。导入时显示未匹配、重复和缺失字段的行级错误；HTTP 密钥留在后端。
3. 运行：选择数据集版本、HTTP 目标或已导入的预测结果，以及指标集，异步执行；可查询进度、取消、失败原因；对单个样本失败进行记录，不把整批结果伪装成成功。文件模式不得调用被测 HTTP 服务。每次运行固定输入来源快照、指标版本、评测模型与参数。
4. 指标：检索指标 Recall@k、Precision@k、MRR（仅有相关文档标注时）；生成指标至少包含基于上下文的忠实度、答案相关性，以及有参考答案时的正确性。逐项记录原始分数、适用性、错误和评分依据。LLM 评测结果标注非确定性，不与确定性指标混为一个总分。
5. 结果：运行列表、概览分布、逐样本详情、两个运行的同数据集对比、CSV/JSON 导出；比较时显示样本增减与评测配置差异。

## 首版不做

不自建向量库或知识库，不承担 RAG 推理，不做在线流量采集、多轮对话、自动生成测试集或自动判定上线。首版聚焦单轮文本问答的离线评测。

## 质量与安全约束

- 相同数据集版本和确定性指标配置应得到相同结果；外部调用的输入输出与错误需要可追溯，敏感值必须脱敏。
- API 与前端分离，使用版本化 JSON 契约；长任务不占用 API 请求生命周期。
- 运行并发、超时、重试和模型费用设置上限；取消后不再提交新样本。
- 服务默认只监听本机回环地址；外部目标地址由本机用户配置，密钥不能写入运行结果、导出文件或日志。
- 自动化验收覆盖数据校验、指标边界、任务状态迁移、API 契约以及核心前端流程。

## 待确认

3. 可用的评测模型提供方、数据传输限制、单次运行预算。
