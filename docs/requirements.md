# 产品需求草案

状态：MVP 范围已澄清，通用 HTTP 连接参数保留可调整默认值。目标是给开发者一套可复现、可追溯的本机 RAG 评测工作台。已确认：一套 Python 后端、React 前端，前后端分离，本机单人使用；单次评测约 100 到 1,000 条样本。

## 已确认的评测对象

首版评测单轮文本 RAG 的检索效果和最终回答。现有样本包含问题、标准答案和相关文档 ID；每题可能标注一个或多个相关文档。检索返回的是片段，每个片段可以归属到一个文档 ID；评测时以文档 ID 为相关性标注单位。

## 用户与主流程

主要用户是本机上的 RAG 开发者。用户导入带问题、标准答案和相关文档标注的数据集；选择调用现有 RAG HTTP API 或导入已有答案与检索结果；配置指标、评测模型与场景评价标准；运行评测；查看总体分数和逐样本证据；导出结果。失败样本可定位到调用错误、导入错误、缺失上下文或具体评分原因。

## MVP 范围

1. 数据集：导入 CSV/JSONL，字段映射与校验；不可变版本。样本包含稳定 ID、问题、标准答案和相关文档 ID 列表。拒绝缺少必要字段、重复 ID 或不合法结构，给出行号与错误原因。
2. 输入方式：HTTP 模式先使用约定的 JSON 契约调用 RAG 服务，支持创建运行前测试连接；真实系统的特定格式通过后续适配器支持。文件模式导入 CSV/JSONL 中已有的答案与有序检索片段，可按样本 ID 匹配已有数据集，也可从同一文件建立数据集。两种方式都归一化为答案、检索片段正文及片段 ID/文档 ID/来源、耗时（若有）和错误。导入时显示未匹配、重复和缺失字段的行级错误；HTTP 密钥留在后端。
3. 运行：选择数据集版本、HTTP 目标或已保存的预测批次，以及指标集，异步执行；首版支持约 100 到 1,000 条样本，并限制同时运行的评测及外部请求数量。HTTP 调用与文件导入都生成不可变预测批次。可查询进度、取消、失败原因；对单个样本失败进行记录，不把整批结果伪装成成功。使用已有预测批次时不得再次调用被测 HTTP 服务。每次运行固定输入来源快照、指标版本、评测模型与参数。
4. 指标：检索指标为 Recall@K、MRR@K、NDCG@K；均以文档 ID 为单位，同一文档的多个检索片段按首次出现顺序去重。相关性为二值标注，NDCG@K 使用二值增益。回答指标为基于上下文的忠实度、答案相关性和相对于标准答案的正确性，主要由大模型按提示词评判。评测模型通过可配置地址、模型名和凭据的 OpenAI 兼容 API 接入，可使用云端或本地服务。逐项记录原始分数、适用性、错误和评分依据；LLM 评测结果标注非确定性，不与确定性指标混为一个总分。
5. 评价标准：系统固定三项回答指标的提示词结构、输入变量和结构化评分输出；用户只编辑各指标的评价标准，并将三项标准作为一个命名场景保存和复用。运行时选择一个场景，运行前可用单条样本预览评分结果。每次运行保存场景标准内容、版本及系统提示词版本快照，避免后续修改影响历史结果。
6. 结果：运行列表、总体指标和分布、逐样本详情、CSV/JSON 导出；显示有效样本数、失败数和不适用数。

## MVP 验收场景

1. 导入含问题、标准答案和相关文档 ID 的数据集后，系统生成不可变版本；缺失字段或重复样本 ID 会标明具体行号，且不会生成半成品版本。
2. 对约定 HTTP 接口运行评测时，每条结果可查看答案、有序片段正文、文档 ID、调用耗时、指标分数和失败原因；接口单条失败不抹掉其他样本的结果。
3. 导入相同答案和检索片段的结果文件后，不发生目标 HTTP 调用；相同数据集和指标配置下，文件与 HTTP 两种模式的确定性检索分数逐样本一致。
4. 检索指标在文档 ID 去重后的序列上分别以 K=10 和 K=20 计算：Recall@K 为 Top-K 命中相关文档数除以相关文档总数；逐样本 RR@K 为 Top-K 内首个相关文档排序位置的倒数，未命中为 0，运行级 MRR@K 为有效样本 RR@K 的均值；NDCG@K 的 DCG 为 Top-K 各位置二值相关性除以 `log2(位置+1)` 之和，再除以将相关文档排在最前时的理想 DCG，未命中为 0。
5. 修改场景评价标准后，可从已有运行发起重新评分，复用不可变预测批次且不再请求被测 RAG 服务；新运行使用新标准，历史运行仍能查看当时的标准、系统提示词版本、模型配置、逐样本评分和评分原因。
6. 报告显示评测配置、有效样本数、失败数和不适用数，并可导出逐样本结果。

## 首版不做

不自建向量库或知识库，不承担 RAG 推理，不做在线流量采集、多轮对话、自动生成测试集、两次运行的对比或自动判定上线。首版聚焦单轮文本问答的离线评测。

## 质量与安全约束

- 相同数据集版本和确定性指标配置应得到相同结果；外部调用的输入输出与错误需要可追溯，敏感值必须脱敏。
- API 与前端分离，使用版本化 JSON 契约；长任务不占用 API 请求生命周期。
- 运行并发、超时、重试和评测模型调用次数设置上限，运行前显示预计调用次数；取消后不再提交新样本。
- 服务默认只监听本机回环地址；外部目标地址由本机用户配置，密钥不能写入运行结果、导出文件或日志。
- 自动化验收覆盖数据校验、指标边界、任务状态迁移、API 契约以及核心前端流程。

## 实现默认值

1. 评测模型由用户配置地址、模型名与凭据；运行前展示模型目标地址和预计评测调用次数。
2. 通用 HTTP 契约支持可选 Bearer Token，默认 30 秒超时；两者均可在目标配置中调整。
3. 每项回答指标输出范围为 0 到 1 的分数及评分原因。系统维护输入变量与结构化输出格式，场景只保存可编辑的评价标准。
