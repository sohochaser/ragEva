# 产品需求草案

状态：MVP 草案，检索计分规则已确认。目标是给开发者一套可复现、可追溯的本机 RAG 评测工作台。已确认：一套 Python 后端、React 前端，前后端分离，本机单人使用；单次评测约 100 到 1,000 条样本；从文档自动生成测试样本并经人工审核发布。

## 已确认的评测对象

首版评测单轮文本 RAG 的检索效果和最终回答，但两类标注的用途不同：端到端答案样本包含问题和标准答案，用于回答质量评测；chunk 召回样本包含问题、一个或多个参考 chunk、这些 chunk 从高到低的相关性顺序，以及每个 chunk 对应的相关文档 ID，用于检索评测。两类样本既可独立导入，也可在同一题中共存。参考和预测 chunk 主要有正文与 `document_id`，通常没有可共享的稳定 chunk ID；正文可能截断或改写，因此需要语义匹配。被测系统返回的 chunk 顺序是预测排序，不能与参考 chunk 的相关性顺序混同。检索指标以 chunk 为命中单位，文档 ID 用于限定候选与解释来源；同一文档的不同 chunk 不能合并为一次命中。

## 用户与主流程

主要用户是本机上的 RAG 开发者。用户可导入外部收集的样本，也可从文档自动生成候选样本，经人工审核后发布数据集版本；随后选择调用现有 RAG HTTP API 或导入已有答案、检索结果；配置指标、评测模型与场景评价标准；运行评测；查看总体分数和逐样本证据；导出结果。失败样本可定位到调用错误、导入错误、缺失上下文或具体评分原因。

## MVP 范围

1. 数据集：导入 CSV/JSONL，字段映射与校验；不可变版本。每条样本有稳定 ID 和问题。答案样本需要标准答案；检索样本需要非空的有序 `reference_chunks` 列表。列表位置就是从高到低的参考相关性顺序，每个 chunk 需要正文和 `document_id`，不要求数值分数或共享 chunk ID。允许两类样本独立导入，也允许同一题同时带两类标注；按实际存在的标注计算对应指标，缺少另一类标注时标记为不适用。拒绝缺少必要字段、重复样本 ID、空参考列表或同一文档下正文完全相同的重复参考 chunk，给出行号与错误原因。
2. 输入方式：HTTP 模式支持约定的非流式 JSON 和流式 SSE 契约，支持创建运行前测试连接；真实系统的特定格式通过后续适配器支持。文件模式导入 CSV/JSONL 中已有的答案和/或有序预测 chunk，可按样本 ID 匹配已有数据集，也可从同一文件建立数据集。两种方式都归一化为按评测类型提供的答案、预测 chunk 正文及其文档 ID/来源、耗时（若有）和错误；chunk ID 可选。只做检索评测时答案不必存在，只做回答评测时需要答案，忠实度还需要预测上下文。导入时显示未匹配、重复和缺失字段的行级错误；HTTP 密钥留在后端。
3. 运行：选择数据集版本、HTTP 目标或已保存的预测批次，以及指标集，异步执行；首版支持约 100 到 1,000 条样本，并限制同时运行的评测及外部请求数量。HTTP 调用与文件导入都生成不可变预测批次。可查询进度、取消、失败原因；对单个样本失败进行记录，不把整批结果伪装成成功。使用已有预测批次时不得再次调用被测 HTTP 服务。每次运行固定输入来源快照、指标版本、评测模型与参数。
4. 指标：检索指标为 Precision@K、MAP@K、NDCG@K，均以参考 chunk 与预测 chunk 的语义匹配和预测排序为依据；相同文档 ID 本身不算命中。首版单独配置向量模型：同一文档 ID 下，计算参考和预测 chunk 向量的余弦相似度，达到该模型配置的阈值才作为匹配候选。阈值随模型和运行快照保存，不跨模型复用固定阈值。每个 Top-K 内实行一对一匹配，一个预测 chunk 最多命中一个参考 chunk，一个参考 chunk 最多被命中一次；合并多个参考内容的预测 chunk 也只计一次。NDCG@K 使用参考顺序推导的相关性增益，规则见下文。保存候选相似度和最终匹配判定；向量按模型版本与正文缓存，判定另外绑定文档 ID、阈值和匹配规则版本，因此检索指标是向量模型辅助指标。回答指标为基于上下文的忠实度、答案相关性和相对于标准答案的正确性，主要由大模型按提示词评判。回答评测模型通过可配置地址、模型名和凭据的 OpenAI 兼容 API 接入，可使用云端或本地服务。逐项记录原始分数、适用性、错误和评分依据；模型辅助指标标注模型与参数，不与其他指标混为一个总分。
5. 评价标准：系统固定三项回答指标的提示词结构、输入变量和结构化评分输出；用户只编辑各指标的评价标准，并将三项标准作为一个命名场景保存和复用。运行时选择一个场景，运行前可用单条样本预览评分结果。每次运行保存场景标准内容、版本及系统提示词版本快照，避免后续修改影响历史结果。
6. 结果：运行列表、总体指标和分布、逐样本详情、CSV/JSON 导出；显示有效样本数、失败数和不适用数。
7. 全链路 trace：使用 OpenTelemetry 标准埋点并在 Jaeger 查看，覆盖评测系统内的导入、调度、目标调用、chunk 匹配、模型评分和结果落库；不采集被测 RAG 服务内部细节。API 到 Worker 的异步任务保持 trace 上下文关联，运行、样本、预测批次及重试尝试可定位。结果页提供对应的 Jaeger 链接。trace 允许记录问题、chunk 正文、提示词及评测模型原始响应；完整原文保存在评测结果中并用 trace ID 关联，不要求逐个流式增量各建一个 span。
8. 自动生成测试样本：按文档集合自动分配生成数量与覆盖范围，生成需要多个 chunk 共同支撑的问题、标准答案和有序参考 chunk；候选经人工审核后发布为不可变数据集版本。生成及发布前均检查同一文档集合的历次候选和已发布样本，避免重复问题进入评测集。具体规则见下文。

## 自动生成测试样本

系统根据同一文档集合的内容自动分配生成数量与覆盖范围，支持构造需要多个 chunk 才能完整回答的问题。每个候选记录问题、标准答案、支撑答案的参考 chunk 正文及其 `document_id`，并保留文档集合身份、文档版本、生成模型和提示词版本，供审核与追溯。参考 chunk 只按与问题的语义相关性从高到低排列，不记录数值关联度；多个 chunk 同样是回答所必需的，也按与问题的语义相关性确定先后。

流程为生成候选样本、人工审核、发布不可变数据集版本。审核者可以修改问题、标准答案和参考 chunk 顺序；未经批准的候选不得用于正式评测。生成时以及审核修改后发布前，均与同一文档集合历次生成的候选和已发布样本查重。不同措辞但考查同一事实且答案相同的问题视为重复，不产生新的可发布样本。文档更新后仍跨版本查重；同一问题因文档更新而出现不同答案时标记冲突，交由人工审核，不自动发布。

生成任务限制模型调用次数与并发，保留失败原因。发布前执行与导入样本相同的字段和参考 chunk 校验；重复或存在未解决答案冲突的候选不得发布。

## 检索匹配与计分规则

- K 默认取 10、20；每个 K 只使用预测列表前 K 个位置，分别计算匹配。文档 ID 不同或余弦相似度低于当前向量模型阈值时，不建立候选边。相同 `document_id` 且合并连续空白、去除首尾空白后正文完全相同的预测 chunk，只允许首次出现者参与匹配；后续重复项仍占预测排序位置，但不产生增益。
- 候选关系可能是一对多或多对多。每个 K 的最终归属选取最大命中数的一对一匹配；有多种最大匹配时，依次优先匹配更靠前的预测位置、将更靠前的参考 chunk 分配给更靠前的预测位置、选择更高余弦相似度，仍相同时按原始输入位置稳定决议。保存每个 K 的最终配对和未配对原因。匹配规则必须有版本号；重新评分不能悄悄改写历史归属。
- 设参考 chunk 总数为 m，第 i 个预测位置的命中标记为 `rel_i`（命中为 1，否则为 0），前 i 位的命中数为 `h_i`。`Precision@K = h_K / K`，运行级 Precision@K 为有效检索样本分数的算术平均。逐样本 `AP@K = [sum(i=1..K, rel_i * h_i / i)] / min(m, K)`，运行级 `MAP@K` 为有效检索样本 AP@K 的算术平均。无命中时各项为 0；预测不足 K 条时，空缺位置视为未命中，Precision@K 仍以 K 为分母。
- 参考列表只给顺序，没有数值等级。MVP 将第 r 个参考 chunk 的增益定义为 `g(r) = m - r + 1`。若预测位置 i 匹配参考位置 r，则其折损增益为 `g(r) / log2(i + 1)`；未匹配位置增益为 0。`IDCG@K` 将前 `min(m, K)` 个参考 chunk 依参考顺序放在预测位置 1 起，按同一公式求和。`NDCG@K = DCG@K / IDCG@K`；无命中为 0。这个线性增益是本项目对顺序标注的约定，结果需显示增益规则版本。

## 通用流式目标契约与计时

通用目标仍以 HTTP POST 接收 `case_id` 和 `question`；请求增加 `stream: true` 时，以 `text/event-stream` 返回 SSE。事件使用 `event` 标识类型，`data` 为 JSON：`answer.delta` 的 `text` 字段携带非空文本增量；`contexts` 的 `items` 字段携带按预测检索顺序排列的完整 chunk 列表，chunk 字段与非流式契约一致；`completed` 表示成功结束；`error` 携带 `code`、`message` 并结束流。`contexts` 可在回答增量前或后到达；需要检索评测或忠实度时，必须在 `completed` 前提供；需要回答评测时，必须至少收到一个非空 `answer.delta`。评测系统拼接回答增量，并将其与 `contexts` 归一化为和非流式响应相同的预测模型。真实系统的其他流式格式由适配器转换，不作为首版通用契约。流开始前的失败使用 HTTP 错误响应；连接中断、缺少结束事件或流内 `error` 不记为成功。

目标响应时间均从发起该次 HTTP 请求时计时。非流式记录从发起请求到完整响应到达的耗时；流式记录客户端收到首个非空回答增量的 TTFT、最后一个非空回答增量的 TTLT，以及收到 `completed` 时的流完成耗时。无回答增量时 TTFT 和 TTLT 为空，不以连接建立、心跳、`contexts` 或结束事件代替回答增量。重试分别记录每次尝试的状态和计时，逐样本保留最终结果及总耗时。

## MVP 验收场景

1. 导入答案样本或 chunk 召回样本后，系统生成不可变版本；缺少各自必要字段、参考 chunk 列表为空或重复样本 ID 会标明具体行号，且不会生成半成品版本。参考列表的数组位置保留相关性顺序，不把它改写成预测排序。
2. 对约定 HTTP 接口运行评测时，每条结果可查看答案、预测 chunk 顺序和正文、对应文档 ID、调用耗时、指标分数、候选余弦相似度、阈值、最终匹配判定与失败原因；接口单条失败不抹掉其他样本的结果。
3. 导入相同答案和检索片段的结果文件后，不发生目标 HTTP 调用；相同数据集、预测内容和语义匹配配置复用已缓存的判定，因此文件与 HTTP 两种模式的检索分数逐样本一致。更换匹配模型或规则会形成新的评测版本，而不覆盖历史判定。
4. 检索指标分别以 K=10 和 K=20 在预测 chunk 的 Top-K 上计算，并按上节规则显示一对一归属、增益与分数。两个参考 chunk 均与一个合并预测 chunk 相似时，该预测 chunk 只能命中其中一个；若它位于预测位置 1，则 Precision@10 为 0.1、AP@10 为 0.5。若预测位置 1 可匹配参考 A/B，位置 2 只可匹配 A，应配为 1-B、2-A，此时 Precision@10 为 0.2、AP@10 为 1。重复返回同一预测 chunk 不增加第二次命中，但仍占排序位置。同一文档下两个不同的参考 chunk 被两个不同预测 chunk 命中时，交换两个预测 chunk 的顺序不改变 Precision 和 AP，NDCG 则按参考相关性顺序变化。跨文档或低于阈值的候选均不命中；零预测结果的三项检索分数均为 0。
5. 修改场景评价标准后，可从已有运行发起重新评分，复用不可变预测批次且不再请求被测 RAG 服务；向量模型和阈值不变时复用已保存的匹配判定，变更时生成新判定。新运行使用新标准，历史运行仍能查看当时的标准、系统提示词版本、模型配置、逐样本评分和评分原因。
6. 报告显示评测配置、有效样本数、失败数和不适用数，并可导出逐样本结果。
7. HTTP 目标分别返回完整 JSON、正常 SSE、流内 `error` 和意外断流时，逐样本结果正确记录答案、上下文、响应耗时或 TTFT/TTLT/流完成耗时及失败原因；正常 SSE 的答案和上下文与等价非流式响应归一化后相同。Jaeger 链接能定位同一样本的目标调用、匹配、评分和落库记录；文件导入样本没有目标调用耗时。
8. 对同一文档集合多次生成候选时，系统自动分配数量和覆盖范围，能生成多个 chunk 共同支撑的问答；审核页显示问题、标准答案、参考 chunk 正文、文档来源及相关性顺序。审核者修改问题、答案或顺序后，只有通过校验且无重复的样本能发布为不可变数据集版本。考查同一事实且答案相同的不同问法不得重复进入可发布候选；文档更新后仍检查历史样本，答案冲突须经人工审核，不自动发布。

## 首版不做

不自建向量库或知识库，不承担 RAG 推理，不做在线流量采集、多轮对话、两次运行的对比或自动判定上线。首版聚焦单轮文本问答的离线评测及基于文档的测试样本生成。

## 质量与安全约束

- 语义匹配与回答评分依赖评测模型，首次判定可能存在波动；相同数据集、预测批次与评测配置复用已保存的判定和评分快照时必须得到相同结果。外部调用的输入输出与错误需要可追溯；问题、chunk 正文、提示词和模型原始响应允许进入 trace，凭据、密钥及认证头不得写入 trace、日志或结果。
- API 与前端分离，使用版本化 HTTP 契约（非流式 JSON、流式 SSE）；长任务不占用 API 请求生命周期。
- 运行并发、超时、重试、回答模型调用次数与向量生成批次设置上限；运行前显示预计外部调用量。允许用代表性样本预览向量相似度与阈值命中情况；取消后不再提交新样本。
- 服务默认只监听本机回环地址；外部目标地址由本机用户配置，密钥不能写入运行结果、导出文件或日志。
- 自动化验收覆盖数据校验、指标边界、任务状态迁移、API 契约以及核心前端流程。

## 实现默认值

1. 回答评测模型和检索匹配向量模型分别配置地址、模型名与凭据；运行前展示目标地址和预计外部调用量。向量相似度阈值与具体模型绑定，运行和导出结果均记录该值。
2. 通用 HTTP 契约支持可选 Bearer Token，默认 30 秒超时；两者均可在目标配置中调整。
3. 每项回答指标输出范围为 0 到 1 的分数及评分原因。系统维护输入变量与结构化输出格式，场景只保存可编辑的评价标准。

## 待确认的 trace 细节

1. Jaeger trace 与评测结果中完整内容的保留期限，以及是否要求在 Jaeger 中直接查看全部正文。
