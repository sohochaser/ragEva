# 实施任务拆解草案

阶段 0 的 MVP 需求规则已明确，详见 `requirements.md`。后续每一阶段以前一阶段的可运行验收产物为入口。

US-001 工程基座已实现：本机启动、API/Worker 健康检查、OpenAPI 契约、React 状态页与 CI 门槛。US-002 已实现：CSV/JSONL 金标准样本导入、字段映射、行级校验、不可变版本和 React 浏览界面。US-003 已实现：CSV/JSONL 预测批次导入、同文件建集、版本绑定及 React 预览。后续故事按依赖逐条实施。

逐条交付的固定编号、依赖、输入输出、失败场景、自动化测试和完成标准见 [用户故事与验收清单](stories.md)。下表是阶段视图，故事验收以该清单为准。

| 阶段 | 交付物 | 验收重点 |
| --- | --- | --- |
| 0. 需求基线 | 固定两类样本、原文与 chunk 来源、下载边界、候选生成审核、本地向量匹配与三项检索指标 | `requirements.md` 给出可测试的 MVP 验收场景 |
| 1. 工程 Harness | 前后端骨架、本机启动方式、CI、测试命令、OpenAPI、Agent 入口 | 新克隆仓库可一条命令启动和测试 |
| 2. 数据集与输入 | 原文与 chunk 清单导入、不可变快照、独立 Token 文档下载、候选生成审核与发布、预测结果导入、HTTP JSON/SSE 连接测试 | 原文下载保留字节和 ID；chunk-only 不提供伪造原文；候选通过审核、查重后发布；两种预测来源归一化 |
| 3. 运行与评测 | 异步执行、状态机、本地向量匹配与指标、在线回答评分、token 用量、场景标准、逐样本证据、OpenTelemetry trace | 检索无 SaaS 向量/生成式模型调用；JSON/SSE 与文件来源可评测；失败、取消、复评和 trace 过期可复现 |
| 4. 前端工作流 | 文档上传与下载配置、生成任务设置与审核、连接、场景配置、运行、结果详情、trace 链接、导出 | 浏览器 E2E 覆盖文档下载、生成不足额、疑似重复放行、JSON/SSE 和文件主路径 |
| 5. 稳定性与交付 | 完整回归、性能与故障验证、部署文档 | CI 全绿，前后端契约与主要运行场景通过 |

每项任务的完成定义：验收条件可运行、自动化检查通过、文档与契约同步、GitHub 上可追踪提交。
