# 实施任务拆解草案

阶段 0 的主体范围已明确，合并 chunk 的计分规则仍待确认，详见 `requirements.md`。后续每一阶段以前一阶段的可运行验收产物为入口。

| 阶段 | 交付物 | 验收重点 |
| --- | --- | --- |
| 0. 需求基线 | 固定两类样本、语义匹配方式、合并 chunk 的命中归属与 NDCG 增益规则 | `requirements.md` 给出可测试的 MVP 验收场景 |
| 1. 工程 Harness | 前后端骨架、本机启动方式、CI、测试命令、OpenAPI、Agent 入口 | 新克隆仓库可一条命令启动和测试 |
| 2. 数据集与输入 | 数据集版本、预测结果导入、HTTP 目标配置与连接测试 | 两种来源生成相同预测模型；错误行可定位 |
| 3. 运行与评测 | 异步执行、状态机、chunk 匹配与指标、场景评价标准、逐样本证据 | 两种来源均可评测；匹配判定与提示词版本可追溯；失败/取消/重试可复现 |
| 4. 前端工作流 | 导入、连接、场景配置、运行、总体与逐样本详情、导出 | 浏览器 E2E 覆盖 HTTP 与文件主路径 |
| 5. 稳定性与交付 | 完整回归、性能与故障验证、部署文档 | CI 全绿，前后端契约与主要运行场景通过 |

每项任务的完成定义：验收条件可运行、自动化检查通过、文档与契约同步、GitHub 上可追踪提交。
