# 实施任务拆解草案

阶段 0 的检索计分规则已明确，详见 `requirements.md`。后续每一阶段以前一阶段的可运行验收产物为入口。

| 阶段 | 交付物 | 验收重点 |
| --- | --- | --- |
| 0. 需求基线 | 固定两类样本、语义匹配方式、一对一命中归属与 Precision@K、MAP@K、NDCG@K 规则 | `requirements.md` 给出可测试的 MVP 验收场景 |
| 1. 工程 Harness | 前后端骨架、本机启动方式、CI、测试命令、OpenAPI、Agent 入口 | 新克隆仓库可一条命令启动和测试 |
| 2. 数据集与输入 | 数据集版本、文档候选生成与审核、预测结果导入、HTTP JSON/SSE 目标配置与连接测试 | 两种预测来源生成相同模型；候选通过审核和查重后发布；错误行可定位 |
| 3. 运行与评测 | 异步执行、状态机、chunk 匹配与指标、场景评价标准、逐样本证据、OpenTelemetry trace | JSON/SSE 与文件来源均可评测；匹配判定与提示词版本可追溯；失败/取消/重试及 trace 关联可复现 |
| 4. 前端工作流 | 导入、生成候选审核、连接、场景配置、运行、总体与逐样本详情、trace 链接、导出 | 浏览器 E2E 覆盖 JSON/SSE、文件及候选审核主路径 |
| 5. 稳定性与交付 | 完整回归、性能与故障验证、部署文档 | CI 全绿，前后端契约与主要运行场景通过 |

每项任务的完成定义：验收条件可运行、自动化检查通过、文档与契约同步、GitHub 上可追踪提交。
