# Harness 开发与交付流程草案

状态：技术栈、输入方式与部署范围已确认。本机单人使用，一套 Python 后端、React 前端，同时支持 HTTP 调用和结果文件导入。当前交付方式为自动化检查通过后在本地提交；推送远程、创建或更新 PR 均需用户另行授权。

## 单项任务闭环

1. 将需求写成可观察的验收条件，记录不在范围内的行为。
2. 拆成可独立验证的小任务，明确允许修改的模块、接口和依赖。
3. Agent 阅读本仓库文档与相关代码，先补足契约和必要的失败测试，再实现功能。
4. 本地执行格式、静态检查、单元测试、契约测试和受影响的集成/端到端测试；对失败进行修复并重跑。
5. 审查差异、确认无凭据和无关生成物、记录测试证据；只有检查通过才在本地按故事提交。
6. 用户授权远程交付时再推送功能分支并创建或更新 PR，GitHub CI 重跑同一套门槛；失败则本地修复、检查、提交后再请求授权推送。需求或架构变化同步更新文档。

## 自动化门槛

- 后端：格式/静态检查、类型检查、pytest 单元与 API/数据库集成测试；覆盖原文解析与切块快照、下载 Token 鉴权、生成不足额和查重审核、本地向量匹配、token 用量来源及 trace 过期。
- 前端：lint、类型检查、组件测试、生产构建。
- 跨端：OpenAPI 契约检查、HTTP JSON/SSE 和文件导入评测、原文下载与候选审核发布的 E2E，以及前端类型与后端响应的一致性检查。
- 无外部付费模型、真实密钥或真实目标服务时也能完成 CI；另设显式触发的真实服务验证。
- GitHub Actions 只在所有门槛成功后允许后续交付步骤；失败时保留日志和报告。

Git 提交应按完成的故事或可独立验收的任务切分，而不是每次保存文件都提交。未经用户明确授权，不推送远程或修改现有 PR。
